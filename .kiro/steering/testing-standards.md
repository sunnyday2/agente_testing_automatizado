# Testing Standards: Playwright & Pytest

## Pytest Configuration

- Use `pytest.ini` or `pyproject.toml [tool.pytest.ini_options]` for configuration
- Mark tests with descriptive markers: `@pytest.mark.smoke`, `@pytest.mark.regression`, `@pytest.mark.e2e`
- Use fixtures for setup/teardown, never raw setup methods
- Shared fixtures go in `conftest.py` at the appropriate directory level
- Test files must be named `test_*.py`, test functions `test_*`

## Playwright Patterns

### Browser Configuration
```python
@pytest.fixture(scope="session")
def browser_context_args(browser_context_args):
    return {
        **browser_context_args,
        "viewport": {"width": 1280, "height": 720},
        "ignore_https_errors": True,
    }
```

### Page Object Model (POM)
- Every page/component gets its own class in `tests/e2e/pages/`
- POM classes expose semantic methods, not raw selectors
- Locators are defined as class-level properties using `page.locator()`
- Methods return `self` for chaining or the relevant data
- Example pattern:
  ```python
  class LoginPage(BasePage):
      def __init__(self, page: Page):
          super().__init__(page)
          self.email_input = page.locator("[data-testid='email']")
          self.password_input = page.locator("[data-testid='password']")
          self.submit_btn = page.locator("[data-testid='login-submit']")

      async def login(self, email: str, password: str) -> "DashboardPage":
          await self.email_input.fill(email)
          await self.password_input.fill(password)
          await self.submit_btn.click()
          return DashboardPage(self.page)
  ```

### Selector Priority
1. `data-testid` attributes (preferred)
2. ARIA roles and labels (`role=button[name="Submit"]`)
3. Text content (`text=Login`)
4. CSS selectors (last resort)

## Allure Integration

- Annotate every test with `@allure.feature()` and `@allure.story()`
- Use `@allure.step()` for complex operations within tests
- Attach screenshots on failure via fixture:
  ```python
  @pytest.fixture(autouse=True)
  def capture_on_failure(request, page):
      yield
      if request.node.rep_call and request.node.rep_call.failed:
          allure.attach(
              page.screenshot(),
              name="failure_screenshot",
              attachment_type=allure.attachment_type.PNG,
          )
  ```
- Use `allure.severity_level` to categorize test importance

## Test Organization

### Unit Tests (`tests/unit/`)
- Test individual functions and classes in isolation
- Mock all external dependencies (ChromaDB, Ollama, Plane.so API)
- Fast execution (< 1 second per test)
- No network calls, no file I/O beyond tmp directories

### Integration Tests (`tests/integration/`)
- Test service interactions (API endpoints, agent flow)
- Use test containers or mock servers for external services
- May use real ChromaDB with test data
- Allowed to take up to 10 seconds per test

### E2E Tests (`tests/e2e/`)
- Full browser-based tests against running application
- Use POM classes exclusively — no raw page interactions in test functions
- Group by feature/flow, not by page
- Each test must be independent (no shared state between tests)

## Generated Tests (`tests/e2e/generated/`)

- Auto-generated tests from URL crawl analysis go here
- Generated files include a header comment with generation metadata:
  ```python
  # Auto-generated by QA Agent from: https://example.com
  # Generated at: 2024-01-15T10:30:00Z
  # Crawl depth: 3, Pages discovered: 12
  ```
- Generated POM classes are placed alongside test files
- Review generated tests before promoting to regression suite

## Test Execution

- Smoke tests: `pytest -m smoke --headed=false`
- Regression: `pytest -m regression --headed=false`
- Single browser: `pytest --browser chromium`
- Parallel: `pytest -n auto` (with pytest-xdist)
- With Allure: `pytest --alluredir=./data/allure-results`
